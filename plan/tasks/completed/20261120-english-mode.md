# Английский режим аудита

## Обзор

Санжар 20.11.2026: «сделаем варик нашего скилла для англ языка, на основе оригинального humanizer». Аудит jev-humanizer сейчас знает только русский. На английском письме клиенту он дал шум: «иностранное вместо русского», длинное тире в «27–28», ★ как эмодзи. Нужен английский режим на основе blader/humanizer, откуда вырос humanizer-ru.

## Контекст

- `jev_humanizer/patterns.py` строит вопросы к Jev по `vendor/humanizer-ru/references/patterns.md`, линтер берётся из `vendor/humanizer-ru/scripts/lint.py`.
- Оригинал: https://github.com/blader/humanizer, MIT, 26 паттернов в SKILL.md с заголовками «### N.».
- Параллельно другой агент гоняет аудит из основного checkout, поэтому работа идёт в worktree `~/projects/_wt/jev-humanizer-en`, ветка `english-mode`. В main сливает Санжар (или оркестратор).
- Первый реальный текст: деловое письмо клиенту в ответ на RFQ, лежит вне репозитория.

## Критерии успеха

- Язык определяется сам по доле кириллицы, флаг `--lang ru|en` его перекрывает.
- Русский режим шлёт в Jev те же запросы, что раньше; старые тесты зелёные без правок.
- В английском режиме нормы делового письма не считаются слопом: «Dear X», «Best regards», нумерованные вопросы в ответе на RFQ, короткое тире в диапазонах, ×, звёзды отелей, отраслевые сокращения.
- `python3 -m unittest discover -s tests` зелёный, сеть в тестах закрыта.
- Прогон первого письма стоит меньше 0,5 USD вместе со всеми прочими вызовами Jev.
